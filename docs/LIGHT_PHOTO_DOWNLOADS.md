# Light online photo downloads

In kiosk Step 4, choose Photo 1-4 or Decorated receipt, then Get download QR. This explicitly uploads only the selected JPEG; capture and print remain local by default. The QR appears only after the upload succeeds. It opens the existing https://www.phototags.app/download/{code} page, using the same 30-minute link expiry and 24-hour cleanup schedule as the APK service. Anyone with the link can access that photo until expiry. Local printing/saving still work offline; creating an online QR requires connectivity and an active Light license.

The existing Light service handles the new signed `photo-upload` action and validates the installation, license, consent and rate limit. It requests an upload slot from the existing https://www.phototags.app/api/upload endpoint. The booth uploads the JPEG directly to that slot in the existing `photobooth-downloads` bucket. The existing `photo_downloads` table, APK API handlers, cleanup policy, download page, licenses and payments are unchanged. No new project, database migration or environment variable is needed. The Light bridge creates no payment and exposes no Supabase service key. Do not clear browser data to troubleshoot a sharing error.

Images are converted to JPEG with a maximum long edge of 1800 pixels. A failed or stale upload never exposes a QR. Changing the selected image/session clears the displayed QR; an in-flight upload is aborted when leaving the screen. Duplicate clicks are disabled and a completed selection is reused while this panel remains open. Download links and signed upload tokens are not saved in license storage or photo-history exports. The photo itself remains available through the existing local history.

Validation uses isolated SQL and a simulated existing upload API/storage endpoint; no production photo is uploaded by the automated checks. Run the existing website regression suite and `node scripts/check-light-integration.cjs <booth-path>`, plus the booth build and kiosk accessibility checks.
