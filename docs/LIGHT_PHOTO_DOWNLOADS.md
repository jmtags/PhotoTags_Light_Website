# Light online photo downloads

In kiosk Step 4, the booth automatically prepares a download QR for the decorated receipt and each raw photo. The codes appear to the right of the receipt on wide screens and stack below it on narrow screens. Settings > Kiosk session can disable automatic generation and offer a Get QR button for each image instead. The welcome screen discloses when automatic uploads are enabled. The QR appears only after the upload succeeds. It opens the existing https://www.phototags.app/download/{code} page, using the same 30-minute link expiry and 24-hour cleanup schedule as the APK service. Anyone with the link can access that photo until expiry. Local printing/saving still work offline; creating an online QR requires connectivity and an active Light license.

The existing Light service handles the new signed `photo-upload` action and validates the installation, license, consent and rate limit. It requests an upload slot from the existing https://www.phototags.app/api/upload endpoint. The booth uploads the JPEG directly to that slot in the existing `photobooth-downloads` bucket. The existing `photo_downloads` table, APK API handlers, cleanup policy, download page, licenses and payments are unchanged. No new project, database migration or environment variable is needed. The Light bridge creates no payment and exposes no Supabase service key. Do not clear browser data to troubleshoot a sharing error.

Images are converted to JPEG with a maximum long edge of 1800 pixels. A failed or stale upload never exposes a QR. Changing an image/session clears its displayed QR; an in-flight upload is aborted when leaving the screen. Duplicate clicks are disabled and completed images are reused from memory when returning to Step 4 in the same session. Starting a new guest session clears that cache. Download links and signed upload tokens are not saved in license storage or photo-history exports. The photo itself remains available through the existing local history.

Validation uses isolated SQL and a simulated existing upload API/storage endpoint; no production photo is uploaded by the automated checks. Run the existing website regression suite and `node scripts/check-light-integration.cjs <booth-path>`, plus the booth build and kiosk accessibility checks.


Settings > Kiosk session also controls the Step 4 automatic start-over countdown (default two minutes, Off or 30 seconds through ten minutes). It uses wall-clock time and checks again on focus/visibility changes, so backgrounding does not extend a session. Printing and unresolved jobs pause the countdown. Once the host resolves a print, the guest gets a fresh interval. Automatic reset clears the guest session and QRs, retains local photo history, and never submits another print. These settings are local to this browser installation; no server or database changes are required.
